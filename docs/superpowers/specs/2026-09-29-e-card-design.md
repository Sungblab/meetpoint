# 전자 명함 설계

작성일: 2026-09-29 · 상태: 승인 대기

## 목적

종이 명함은 받고 나서 지갑에 넣고 다시 보지 않는다. Meetpoint에서는 모두가 같은 전자 명함을 갖고, 서로 연결된 순간 한 번 눌러 상대를 휴대폰 연락처에 "만난 이유"와 함께 저장하게 한다.

성공 기준: 서로 연결된 두 사람이 명찰 뒷면의 전자 명함에서 "연락처에 저장"을 누르면, 휴대폰 연락처 추가 화면에 이름·한 줄 소개·전화·이메일과 메모(행사 이름, 날짜, 만난 이유)가 채워져 나온다.

## 정한 것 (사용자 확인)

- 전자 명함은 서로 연결된 사람에게만 보인다. 지금의 연락처 규칙과 같다.
- 명함 이미지는 저장하지 않는다. 모두가 Meetpoint가 디자인한 전자 명함 하나로 통일한다.
- "명함 사진으로 채우기"는 입력 도우미로 남긴다. 사진은 저장하지 않고 글자만 읽어 칸을 채운다.
- 구조화된 칸(A안): 전화번호, 이메일, 기타 연락처.

## 범위 밖

명함 이미지 저장, 회사·직함 별도 칸, 행사 뒤 이메일 정리, 명함 QR.

## 데이터

- `participants`에 `phone VARCHAR(30)`, `email VARCHAR(100)`를 추가한다. 둘 다 기본값 `''`.
- 기존 `contact`는 "기타 연락처"(카카오톡 ID, 링크드인 등)로 그대로 쓴다.
- 운영 DB에는 마이그레이션 도구 없이, `Database.create_all()`이 테이블을 만든 뒤 모델에는 있고 DB에는 없는 칸을 `ALTER TABLE ... ADD COLUMN ... DEFAULT ''`로 추가한다. SQLite와 Postgres 모두 같은 코드로 동작한다.

## 입력

- 입장·내 명찰 양식의 "연락처" 한 칸을 "전자 명함" 묶음으로 바꾼다.
  - 전화번호: `type=tel`, `autocomplete=tel`. 비어 있거나 숫자·`+`·`-`·공백·괄호로 7~30자.
  - 이메일: `type=email`, `autocomplete=email`. 비어 있거나 `@`와 그 뒤에 `.`이 있는 형식, 100자까지.
  - 기타 연락처: 기존 `contact`, 100자까지.
- 셋 다 선택이다. 안내 문구: "서로 만나고 싶어요를 누른 사람에게만 보여요".
- 한 줄 소개가 명함의 소속·직함 줄이 된다. 회사·직함 칸은 따로 두지 않는다.
- 양식 아래에 "연결된 사람에게 보이는 내 전자 명함" 미리보기를 두고, 적는 대로 채운다(`badge.js`).

## 명함 사진으로 채우기

- `CARD_SCHEMA`에 `phone`, `email`을 추가하고 `contact`는 기타(웹사이트·SNS)로 바꾼다. 휴대폰 번호가 있으면 휴대폰, 없으면 대표 번호.
- `/r/{code}/card` 응답에 `phone`, `email`을 더하고 `join.js`가 해당 칸을 채운다.
- 추천 계산에는 여전히 연락처 정보를 보내지 않는다(`as_prompt_dict` 변경 없음).

## 전자 명함 화면

- 서로 연결되면 명찰 뒷면(지금 연락처 자리)에 가로형 명함 카드를 보여준다.
  - 이름, 한 줄 소개
  - 전화(누르면 `tel:`), 이메일(누르면 `mailto:`), 기타 연락처. 적은 것만 보인다.
  - "연락처에 저장" 버튼
- 셋 다 비어 있으면 지금처럼 "연락처는 적지 않았어요. 찾는 법을 보고 직접 찾아가 보세요."
- 아이콘은 `base.html`의 `<symbol>`에 전화·메일·링크를 더한다. 색은 기존 규칙대로 관계·연결 상태에만 쓴다.

## 연락처에 저장 (vCard)

- `GET /r/{code}/api/vcard/{participant_id}`: 참가자 쿠키가 있고 대상과 서로 연결된 경우에만 200, 아니면 404.
- `text/vcard; charset=utf-8`, 파일 이름은 `{이름}.vcf`(RFC 5987 인코딩).
- vCard 3.0: `FN`, `N:;{이름};;;`, `TITLE:{한 줄 소개}`, `TEL;TYPE=CELL`, `EMAIL;TYPE=INTERNET`, `NOTE:Meetpoint · {행사 이름} · {방을 만든 날짜 YYYY-MM-DD} · 만난 이유: {저장하는 사람이 본 추천 이유}` 그리고 기타 연락처가 있으면 다음 줄에 `기타 연락처: …`.
- 값의 `\`, `,`, `;`, 줄바꿈은 RFC 6350 규칙대로 이스케이프한다.

## API

- `/r/{code}/api/state`의 `people[]`에 `phone`, `email`을 더한다. 서로 연결됐을 때만 값이 있고 아니면 `null`. `contact`와 같은 규칙.
- 만나고 싶어요 응답(서로 연결된 경우)에도 `phone`, `email`을 더한다.

## 개인정보 처리방침

- 선택 항목 "연락처"를 "전화번호, 이메일, 기타 연락처"로 바꾼다.
- "서로 연결된 상대는 내 전자 명함을 자신의 휴대폰 연락처에 저장할 수 있습니다. 저장된 연락처는 상대 기기에 남으며 서비스에서 지울 수 없습니다."를 2번 항목에 더한다.

## 테스트

- 연결 전: state와 vCard 엔드포인트에서 전화·이메일이 나오지 않는다(404).
- 연결 후: vCard에 이름·전화·이메일·만난 이유가 들어 있고 이스케이프가 맞다.
- 입력 검증: 잘못된 전화·이메일은 오류 메시지를 낸다.
- 오래된 DB: `phone`, `email` 칸이 없는 `participants` 테이블에 `create_all()`이 칸을 더한다.
- 명함 읽기: 가짜 AI 응답의 `phone`, `email`이 `/card` 응답에 실린다.
